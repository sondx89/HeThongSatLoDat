# Optional SSD1306 display

**Status:** Host-tested service/driver contract; hardware transport and board
wiring are not approved or verified.

The display service accepts one copied `DisplaySnapshot` at a time and formats
fixed-size ASCII lines without dynamic `String` allocation. It alternates the
calibration and alert pages on a configured 2-second interval. Invalid,
non-finite or stale fields are shown as `--`; stale snapshots are marked
`DATA STALE`. The alert page is inverted only for a valid danger state.

The service and driver are disabled by default. To enable them, the application
must inject an `ISsd1306Transport` that shares the approved I2C bus instance
with the MPU9250, enforces the configured finite transaction timeout, and
confirms the actual display address. `0x3C` is only the DOCX reference and is
not installed as a default. The current repository does not provide a
revision-specific I2C bus/address approval or a physical SSD1306 transport.

`DisplaySnapshot.caseNumber` and `caseName` are caller-provided optional fields.
P10's DemoRulePolicy has not been implemented in this requested P11–P17
sequence, so no CASE is generated by this display service. Until a producer
supplies those values, the CASE line is `CASE --`. No display operation is
wired into sensor acquisition, risk evaluation or logger task execution.

- [ ] Confirm display part number, voltage, I2C address and pull-up/loading.
- [ ] Confirm the display and MPU9250 use the same initialized I2C bus instance.
- [ ] Verify finite I2C timeout behavior and bus recovery on a physical device.
- [ ] Verify 128x64 readability, page cadence, danger inversion and stale markers.
- [ ] Disconnect/display-fault test confirms sensors, risk and logging continue.
