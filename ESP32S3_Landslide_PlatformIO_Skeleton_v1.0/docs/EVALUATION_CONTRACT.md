# Host Evaluation Contract v1

**Status:** Bounded host-only reports and guarded regression metrics. This
contract does not define a target, authorize model training, or make field,
accuracy, or safety claims.

## Inputs and bounds

`EvaluationRunner` accepts at most 4,096 window records per call. Callers
provide an explicitly approved feature schema (version, ID, hash, and count),
provenance, split, feature vector, and optional annotation/prediction
references. References are borrowed only during `evaluate()`. No heap-backed
storage, inference, label generation, or quality reclassification occurs.

The runner reports the upstream rejection count supplied by the caller and
counts malformed records, rejected/ineligible windows, schema mismatches, and
excluded labels separately. It propagates the feature vector's existing
window eligibility, rejection reason, and channel-quality states; it does not
replace `DataQualityService`. Feature statistics are indexed by the caller's
approved schema order. Missing or nonfinite features count as missing and are
never imputed or used as zero.

Reports are grouped by data origin, evidence class, and train/validation/test
split. They include window/feature eligibility counts, rejected counts,
quality-state/rejection distributions, channel-quality counts, eligible and
excluded label counts, prediction availability, and per-feature missingness,
finite count, min/max/mean/population variance.

## Regression metrics gate

Metrics are enabled only when the caller provides both an approved
`AnnotationTargetContract` and an explicit `regressionMetricsApproved` gate.
The repository does not currently have an approved landslide target contract,
so normal project evaluation must leave this gate closed. The gate represents
approval of both target meaning and the scalar regression output mapping; it
does not authorize a probability or risk interpretation.

An eligible label must be an `ACCEPTED` annotation with a valid finite target
value, exact target contract identity, matching dataset/site/session/boot and
overlapping half-open time interval, and matching provenance. Independent
metrics accept only GT1-GT4 independent annotations. Synthetic metrics accept
only `SYNTHETIC`/`GT5` `SYNTHETIC_PROXY` annotations and are stored separately
in `syntheticProxyMetrics`, with CSV scope `SYNTHETIC_PROXY`. Proxy metrics are
not field metrics and must not be called landslide accuracy.

Prediction pairs require `InferenceStatus::Ok`, exactly one finite raw output,
and a finite valid scalar `predictionValue`. The runner does not infer a target
unit/range, select a class, or use `RiskManager` output. MAE and RMSE are
reported for available eligible pairs. R-squared is absent when the paired
targets have no variance. Target min/max are based on eligible labels, even if
a corresponding prediction is unavailable.

When target approval is absent, labels are excluded from metric counts and all
metric fields remain invalid/empty. Feature and quality reports still run.
Synthetic-only results remain explicitly GT5.

## CSV reports

The shared bounded `CsvRowWriter` produces:

- `evaluation_summary.csv`: one row per origin/evidence/split grouping,
  including window counts, exclusions, target range, metric scope, pair count,
  and only the metrics enabled by the target gate.
- `feature_distributions.csv`: one row per approved feature index with observed
  windows, missing/nonfinite counts, finite count, and distribution statistics.

Both use project-local schema version 1, UTF-8, comma separators, quoted fields
as needed, LF, and decimal dot. Buffer exhaustion and formatting errors are
reported; rows are never silently truncated. The row-level `evaluation.csv`
artifact and residual inspection export remain separate future work.

## Limitations

The result is only as independent as caller-provided labels, provenance, split,
and schema approvals. The runner cannot infer whether source groups are
independent, whether annotations are scientifically valid, or whether the
target is meaningful. Synthetic-only tests are not field tests. No HIL or
actual-model evidence is generated by this host component.
